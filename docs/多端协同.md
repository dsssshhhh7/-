# 多端协同使用说明

这套方案用于同一台电脑上的多个 Codex 项目任务之间传话和协作。它可以安装到另一台电脑独立使用，但当前不支持两台电脑之间实时互通。

## 使用前准备

1. 按 [安装与迁移](安装与迁移.md) 安装并验证 `team-codex` 插件。
2. 安装或升级插件后关闭旧任务，新建 Codex 任务；旧任务不会热加载新 Skill。
3. 如果需要 Full 自动创建各端任务，先把 Java、PHP、Android、iOS 等目录添加为当前电脑的 Codex 项目。

验证命令：

```powershell
pwsh -NoProfile -File .\scripts\verify-install.ps1
```

只有同时看到 `installed = true` 和 `enabled = true` 才算安装完成。

## 先统一命名

一个 Codex 任务只处理“一个需求 + 一个端”，代号使用：

```text
<需求号>-<端>
```

例如：

```text
RM316-总控
RM316-Java
RM316-PHP
RM316-安卓
RM141-Java
RM141-安卓
```

不同需求并行时，不要只叫“Java”“PHP”或“安卓”，否则无法精准路由。

## 场景一：传给某个项目任务一句话

### 1. 手动创建各端任务

在 Java 项目目录下新建 Codex 任务，输入：

```text
代号叫 RM316-Java。当前任务只处理 RM316，负责 Java+React。
```

在 Android 项目目录下新建 Codex 任务，输入：

```text
代号叫 RM316-安卓。当前任务只处理 RM316，负责 Android。
```

PHP、iOS 等端同理。代号登记后会显示在任务标题中。

### 2. 直接传话

在任意已登记任务中输入：

```text
传给 RM316-安卓：请确认 RM316 的客户类型字段当前如何处理并回复一次。
```

点对点传话不需要建组，也不需要 `/team join`。显式写法与自然语言等价：

```text
/team say RM316-安卓 请确认 RM316 的客户类型字段当前如何处理并回复一次。
```

目标任务会收到原话并被原生任务消息唤醒；如果它正在执行长操作，消息会排队，因此不能承诺固定 5 秒。接收方最多自动回复一次，回复消息不会再次触发自动回复，以防无限循环。

## 场景二：多个端共同讨论一个需求

有两种流程。你可以自己在各项目新建任务，也可以明确要求 Full 创建真实项目任务。

### 流程 A：你手动创建各端任务

#### 1. 在 Full 建立总控

在 `ai_dev_full` 项目中新建任务，输入：

```text
代号叫 RM316-总控。
为 RM316 建立多端讨论组，参与端为 Java+React、PHP、安卓。
先整理需求材料和初始方向，等我确认后再让各端加入。
```

也可以显式输入：

```text
/team join RM316
```

`/team join RM316` 只会让当前这个任务创建或加入 RM316 组，不会自动创建其他端任务。

#### 2. 人确认初始方向

总控把初始方向呈现给你后，你确认：

```text
方向确认，讨论组设为就绪，可以让各端加入。
```

AI 的推导、其他任务附议或全组无人反对，都不等于人确认。

#### 3. 在各工程手动新建任务并入组

Java 项目任务：

```text
代号叫 RM316-Java。负责 RM316 的 Java+React。
/team join RM316
```

PHP 项目任务：

```text
代号叫 RM316-PHP。负责 RM316 的 PHP。
/team join RM316
```

Android 项目任务：

```text
代号叫 RM316-安卓。负责 RM316 的 Android。
/team join RM316
```

中途加入的任务会读取当前共识、材料、成员和已有约定，即“自动补课”。

### 流程 B：让 Full 自动创建各端任务

你仍然需要先在 Codex Desktop 中登记各个项目。然后在 Full 项目任务中明确输入：

```text
为 RM316 启动多端协作。

参与端：Java+React、PHP、安卓。

先建立 RM316 讨论组并让我确认初始方向。确认后，请在 ai_dev_java、ai_dev_php、XbTerminal_waiqin 对应的真实 Codex 项目中创建任务，代号分别为 RM316-Java、RM316-PHP、RM316-安卓，让它们加入 RM316、自动补课并讨论。

禁止创建 projectless 任务。创建后检查每个任务的 projectId 和工作目录。当前先分析，不开发。
```

如果希望效果和手动从项目目录新建任务一致，再加一句：

```text
各端任务使用 local 项目目录。
```

如果各端随后要并行开发，可以改为：

```text
各开发任务使用隔离 worktree，但仍必须归属于对应 Codex 项目。
```

Full 自动创建时必须遵守以下门槛：

1. 读取当前电脑的 Codex 项目列表；
2. 找到目标工程对应的非空 `projectId`；
3. 以真实项目任务创建；
4. 创建后核对 `projectId` 和工作目录；
5. 找不到项目就停止并报告，不能退化成 `projectless`。

Codex 会在侧边栏创建并运行这些任务，但不保证自动切换到每个任务的前台。项目任务也可能同时出现在“最近”中；判断它是否真的归属于工程，要看项目分组、`projectId` 和工作目录，不能只看“最近”。

## 组内讨论与拍板

各端入组后，在任一组内任务中输入：

```text
同步给全组：请各端检查本端影响范围、依赖和交接点。
```

或：

```text
/team tell 请各端检查本端影响范围、依赖和交接点。
```

只想通知某一端时，直接使用点对点写法：

```text
同步给 RM316-安卓：Java 端的契约结论已更新，请复核 Android 影响。
```

组内消息会保存流水和处理回执。只有跨端契约、分工、依赖或需要另一端继续工作的内容才应同步；本端调试日志和未核实猜测不应广播。

遇到需要人拍板的事项时，各端应暂停 AI 往返，由总控集中呈现问题。你确认后可以输入：

```text
方案确认，通知各端按分工开发。不要推送或部署，完成后回组报告。
```

传话和入组不会自动授予代码修改、提交、推送、部署、删除或对外发送权限，各任务仍以其中人的明确授权为准。

## 结案

事情彻底完成后，在组内任务输入：

```text
/team close RM316
```

结案不可逆，执行前必须再次获得人的确认。完成后会生成唯一结案文档并关闭活动组。

## 常用命令

| 命令 | 作用 |
|---|---|
| `/team name <代号>` | 登记当前任务代号 |
| `/team say <代号> <内容>` | 点对点传话 |
| `/team book` | 查看地址簿和在线情况 |
| `/team join <组名>` | 当前任务创建或加入组 |
| `/team tell <内容>` | 向全组发送消息 |
| `/team who` | 查看成员和待处理数量 |
| `/team inbox` | 查看未处理消息 |
| `/team catch` | 读取当前共识和成员 |
| `/team log` | 查看组流水 |
| `/team ack` | 写入处理回执 |
| `/team leave` | 当前任务退出组 |
| `/team close` | 人确认后结案 |
| `/team doctor` | 检查插件和账本状态 |

## 真实边界

- 当前只支持同一台电脑上的 Codex 任务互通。
- 安装到另一台电脑后，那台电脑可以独立使用；两台电脑不会自动互传消息。
- 消息只有同时写入共享账本且成功发送 Codex 原生任务消息，才能称为“已送达并唤醒”。
- busy 任务的消息会排队，不能承诺固定唤醒时间。
- Codex 与 Claude Code 的核心使用效果可以对应，但底层唤醒方式和界面并非逐字相同。
- Full 内部临时 analyst subagent 与侧边栏中的持久项目任务不是同一概念；跨项目持续协作应创建真实项目任务。

更简洁的日常操作见 [使用手册](使用手册.md)，安装、更新和换机见 [安装与迁移](安装与迁移.md)，技术机制见 [架构与真实边界](架构与真实边界.md)。
