# 安装、更新与迁移

## 新电脑安装

### 1. 安装依赖

- Codex Desktop
- Git for Windows（需要 Git Bash）
- PowerShell 7 (`pwsh`)

### 2. 克隆并安装

```powershell
git clone https://github.com/dsssshhhh7/-.git codex-team
cd codex-team
pwsh -NoProfile -File .\install.ps1
```

安装器会完成四件事：

1. 把插件源码原子复制到 `~/plugins/team-codex/`；
2. 创建或更新 `~/.agents/plugins/marketplace.json`；
3. 调用 Codex CLI 执行 `plugin add team-codex@personal`；
4. 检查真实安装版本，而不是只检查文件是否存在。

安装或升级后必须新建 Codex 任务。已经打开的任务不会热加载新 Skill。

### 3. 验证

```powershell
pwsh -NoProfile -File .\scripts\verify-install.ps1
```

只有同时看到 `installed = true` 和 `enabled = true` 才算完成。

## 自动安装

本仓库的 `.codex/hooks.json` 在 SessionStart 调用安装器。第一次用 Codex 打开本仓库时，需要信任项目 Hook。自动安装完成后仍需再新建一个任务。

## 更新

```powershell
pwsh -NoProfile -File .\update.ps1
```

它只执行快进拉取 (`git pull --ff-only`)，然后重新安装。仓库有分叉或冲突时会停止，不会强制覆盖本地改动。

## 项目准备

希望 Full 自动创建 Java、PHP、Android 或 iOS 任务时，要先在 Codex Desktop 中把相应目录添加为本地项目。自动创建必须绑定真实项目；找不到目标项目时应停止，不能创建成 `projectless`。

项目任务有两种环境：

- `local`：直接使用项目主目录，效果最接近手动从该项目新建任务；
- `worktree`：仍归属同一项目，但在隔离 Git worktree 中工作，适合并行开发。

## 迁移协作数据

插件和配置可以在另一台电脑直接重新安装。运行数据默认位于：

```text
~/codex-team/
```

不建议把整个目录直接复制到另一台电脑，因为地址簿和收件箱包含旧机器的 Codex `threadId`，复制后无法唤醒新机器的任务。

推荐做法：

1. 新电脑只安装插件；
2. 在各项目新建任务并重新登记代号；
3. 需要保留历史时，只复制已完成的结案文档或人工确认过的共识归档；
4. 不复制活动地址簿、会话目录和未处理收件箱。

## 跨机器边界

“另一台电脑可以复用”表示它可以独立安装和运行同一套协作方案，不表示两台电脑可以互相传话。当前消息账本和 Codex 任务工具都是单机范围。跨机器协作需要另建共享服务端、鉴权、消息队列和在线状态协议，本仓库没有伪装实现这些能力。
